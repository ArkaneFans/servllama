# 聊天思考深度

## 产品与保存范围

- 固定七档：关闭、自动、低、中、高、超高、最大。默认自动。
- 助手设置页与聊天输入栏共用滑块；拖动预览，松手提交，图标跟随档位。
- 云端模型配置只增加 `supportsThinking`。未声明支持时隐藏聊天入口并省略思考参数，助手的档位仍保留。
- `Assistant.reasoningLevel` 存入现有 SQL `config` JSON。聊天页修改当前助手，影响该助手的后续请求；不增加会话覆盖或按模型记忆。
- 旧配置缺少字段时分别读取为自动、未声明支持，无需 SQL 迁移或独立标记。
- 本地聊天先按通用 OpenAI 请求形式透传；不探测模型能力、不修改插件或服务器启动流程。

## 请求链路

助手档位 → `ChatRunConfig` 快照 → `ChatRunner` → `ChatProtocolClient.requestBody`。

一次 Run 的首次请求与工具续轮共用冻结的助手配置。新设置在下次 Run 生效。模型的思考标记用于请求构造，不作为运行中的权限撤销条件。

参数转换集中在一个函数，只依据现有三种协议，不判断供应商地址或模型名称：

| 接口 | 转换 |
|---|---|
| OpenAI Chat Completions | `reasoning_effort`；关闭为 none，自动省略，其他档位直接使用等级名称 |
| Anthropic | 关闭使用 `thinking.type: disabled`；自动使用 adaptive 并请求 summarized；其他档位额外传 `output_config.effort` 等级名称 |
| Gemini | `generationConfig.thinkingConfig`；关闭为预算 0，自动省略预算，其他档位使用固定预算；开启时请求思考内容 |

Gemini 预算档位使用 1,000 / 2,000 / 8,000 / 16,000 / 32,000 tokens。具体服务端与模型对字段、等级和预算的支持由其接口负责。

Anthropic 使用 adaptive 时省略温度，输出上限沿用基础请求配置。其余基础请求参数沿用现有行为，不增加自定义预算、供应商兼容分支、请求体编辑器、动态能力探测或新启动链路。

## 验证

- 助手配置和模型标记保存、重载后保持一致，旧 JSON 正常读取。
- 模型标记控制聊天按钮；聊天入口与助手入口修改同一字段。
- 各协议的档位、自动/关闭行为和 Gemini 预算转换正确。
- Run 快照和工具续轮保持同一档位，下一次 Run 使用新设置。

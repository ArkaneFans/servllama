## 服务操作与聊天目标分离

服务器按钮是显式控制本地服务的入口，模型按钮负责当前聊天的模型选择，两者不再互相替代。

1. 本地服务空闲：点击服务器按钮，先弹出引擎选择。取消不启动服务。
2. 选择引擎后，有已选默认模型则启动；没有则弹出该引擎的本地模型列表，点选后完成启动。没有可用模型时显示空状态及发现模型入口。
3. 上述流程不写 `ChatTarget`，不改变当前会话、助手或草稿。尤其在云端聊天中启动本地服务，仍然使用原供应商模型聊天。
4. 本地服务运行中：按钮显示停止含义，点击停止实际运行的服务，包括与聊天模型不同的已发布服务。这是用户显式停止操作；聊天模型选择仍不能自动替换另一已发布模型。
5. 启停处理中禁用重复操作；失败继续使用现有错误提示，取消模型面板不启动。运行时仍负责引擎互斥、模型驻留和停止失败后的资源保留。
6. 快捷启动沿用私用服务模式：回环监听及临时密钥；对外服务仍从服务器页面启动。补选模型路径也统一采用相同模式。没有新增运行时、模型目录或调度器。

云端聊天的输入提示及模型选择不因本地服务加载而被错误显示为“加载模型”。正在发送时沿用现有会话操作限制。

## 档案数据

`UserProfile` 只保存 `name`、`avatar`、`description`。读取旧记录时，以已有 `description` 优先，否则将旧 `preferences` 作为描述；旧称呼字段不再使用。保存后不再写 `addressAs`、`preferences`，显式清空描述不会恢复旧值。保留原有长度校验、头像处理及编辑草稿机制，不增加数据库迁移或双写。

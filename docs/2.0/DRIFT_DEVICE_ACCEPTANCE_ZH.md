## 移除的开发期冗余

1. `ChatSessionRepository._upgradeConversationSettings`：启动时从旧 Run / 助手默认模型推断会话归属和目标。当前会话独立持有这些设置，缺失时要求明确选择。
2. `AgentRepository.retireWorkspace`：一次性移除旧文件工具授权及旧结果链接。文件工具已经退休，当前授权仍受工具注册表限制。
3. `GenerationRunRepository.removeLegacyOrphans`：开发版删除规则变更后的一次性全库孤立记录扫描。保留正常消息删除时的 `deleteUnreferenced` 和恢复时不重建已删除消息的检查。
4. `AssistantRepository.initializeProviders` 中的旧自由输入模型补全：初始化只补齐缺失预设，不从历史目标增加供应商模型授权。

设备在清理前已具备 `workspaceRetiredV1`、`messageRunOwnershipV1`、`providerCatalogV1` 标记，全部会话已有 target 键。已有标记保留为无行为的历史记录，不为删掉几条元数据再增加迁移。

不再承诺对每个早期未发布 2.0 数据格式进行补全；本次设备已先完成旧迁移再安装清理版。其他仍停留在早期开发快照的测试设备应先用 dev.14 完成过渡。

## 保留的必要兼容

- 1.x Hive 会话、消息、版本、GGUF 和下载任务导入，以及凭据迁移。
- 独立的聊天/库存完成标记：合并会让已完成聊天导入的开发安装重复读取旧数据，或遗漏库存；旧 Hive 不能自动删除，也不能恢复双写。
- schema 5 和现有升级入口：重置版本号会使当前设备数据库倒退，简短的幂等建表逻辑没有清理收益。
- Run / 工具 / 语音崩溃恢复、附件引用检查及已登记文件的删除重试。旧工作区仅按登记记录和严格路径边界清理，不扫描任意目录。
- 小型字段读取兼容与 1.x llama-server/凭据迁移不在这次删除范围内。

后续正式验收继续按 [存储迁移指南](STORAGE_MIGRATION_ZH.md) 使用保留数据的 1.x 安装测试首次迁移；再冷启动确认不重复导入。不要通过清数据来替代覆盖升级验收。

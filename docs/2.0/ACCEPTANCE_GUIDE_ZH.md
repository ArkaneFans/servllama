## 6. Agent、网络搜索、Skill、MCP

消息内工具过程是默认入口；会话级“工具调用记录”集中查看所有保留版本的回执，已移除工作区和文本导入。工具记录按当前回复版本的 Run 显示；空正文的工具回复取消后仍保留，删除版本清理对应独占记录，历史查看和版本切换均不重执行。

最小冒烟：开启时间和询问用户工具，发起请求后直接在助手回复内回答，确认状态完成及模型续答；需要审批测试时使用受控远程 MCP。再取消一个尚无文字、等待回答的请求，冷启动后检查取消卡片仍存在且没有有效审批按钮。完整步骤与已执行范围见[工具过程设计](CHAT_TOOL_ACTIVITY_ZH.md#验证与验收)。

先在「助手管理 → 目标助手 → 本地工具/技能/MCP」启用测试所需能力。网络搜索默认未授权；勾选后显示供应商与结果上限，默认 Bing/5 条，无需 API key。供应商和模型都需支持工具调用。搜索使用步骤及实际验证边界见[网络搜索说明](WEB_SEARCH_ZH.md)。可准备一个简单 Skill：

~~~markdown
---
name: acceptance-checklist
description: 根据用户材料整理三项检查清单
---
阅读用户提供的材料，列出三个可执行检查项。缺少关键材料时先询问用户。
~~~

保存为 SKILL.md，在「设置 → 技能与 MCP」导入；ZIP 包可包含同目录的文本参考资料。Skill 是数据和说明，不提供脚本执行。

MCP 使用一个可观察调用日志、可模拟延迟/断线的测试服务。两种传输各测一次；只批准在测试数据上执行的操作。

| 编号 | 操作 | 预期 |
|---|---|---|
| A01 | 授权时间、询问；要求先查询时间再询问用户 | 助手消息内按顺序显示工具卡片，就地回答、状态与续答更新；拒绝正常收尾，展开可查看回执（dev.22 起不再导出） |
| A02 | 对受控 MCP 调用连点批准；撤销权限后再点击旧批准 | 同一调用只执行一次；旧批准不能执行已撤销操作 |
| A03 | 受控 MCP 返回超过 16 KiB 的成功/失败结果 | 保存带截断提示的片段，卡片明确仅可查看该片段；无工作区文件或 read_file 指引 |
| A04 | 设低轮次/调用数/时限，让模型持续调用工具；等待审批超过时限 | 有明确预算停止原因；旧审批不能复活已结束 Run |
| A05 | 对完成的工具回答使用“重新表述”，再明确“重新执行任务” | 前者不调工具；后者新 Run、新记录、新审批，旧批准不复用 |
| A06 | 调用有副作用 MCP 后让响应断开，重开应用 | 无法确认结果的调用显示 unknownOutcome；不自动重试，先核对服务端实际状态 |
| A07 | 绑定 Skill、按需读取资源；导入含脚本包、链接包、越界包、重复路径包 | 静态文本可读；脚本不执行；非法归档拒绝；删除后助手绑定清理 |
| A08 | Streamable HTTP：初始化、tools/list 分页、调用、session 失效、401 | 正常映射结果/错误；不会因会话重建自动重放写调用 |
| A09 | SSE：初始化、endpoint、列工具、调用、断流 | 正常收发并在取消/关闭后释放连接；未知执行结果可追踪 |
| A10 | 分别保存 Bearer 和自定义头；保留/清除其中一种；改密钥、删服务器 | 两种认证独立保存；非法保留头/重复头/换行注入拒绝；失效授权及时撤销 |
| A11 | 正在审批时关闭助手工具权限、删除 Skill/MCP，再批准旧卡片 | 执行前重新核对；已撤销调用不能执行；旧依赖授权被清理 |
| A12 | 启用 Bing 搜索，查询 Flutter 官方文档，查看工具过程与最终回答并点击来源 | 搜索结果包含标题、来源 URL、摘要和获取时间；来源卡片可打开浏览器，模型收到结果后续答；不会宣称已读取网页全文 |
| A13 | 切换 DuckDuckGo 并设置结果上限为 3，新建对话请求更多结果；搜索运行时再改供应商或撤销权限 | 新 Run 使用新配置且最多 3 条；旧授权域的 Run 停止，不会静默换供应商；网络受阻如实记录，不按空结果判通过 |
| A14 | 搜索等待时停止聊天；通过受控响应分别模拟超时、429、验证页面和异常 HTML | 主动取消终止请求；失败有明确回执和提示，搜索自身超时不终止整个聊天，不自动重放同一调用或绕过验证 |
| A15 | 完成搜索后重新打开历史或使用「重新表述」，在日志页查询 agent.search | 读取已保存的来源与回执，不重新搜索；日志只有供应商、ID、数量、长度、耗时、状态，不含搜索词/摘要/URL；会话删除后其工具回执随之删除 |
| A16 | 在含工具的回复间切换版本，再重新表述或手工编辑 | 工具区只显示选中版本对应 Run；无 Run 的编辑版本不继承旧工具；仅重新表述不再次执行或将旧记录冒充本轮调用 |
| A17 | 在尚无正文的提问/写文件审批时停止，退出并冷启动后回看 | 助手回复、版本及取消回执保留；历史可以展开，审批不可复活；Run/工具记录与服务请求数不增加 |
| A18 | 320 dp、2 倍文字下展开长参数/结果与 MCP 名称；模拟历史读取失败后重试 | 内容可滚动查看，按钮可用且无溢出；重试只读历史，不执行工具；流式 token 更新不反复查询回执 |

默认预算是 8 回合/16 工具/2048 输出 token/24000 字符上下文/180 秒，审批计入总时限。Token 无 usage 时按字符估算；验收真实 token 用量时读取供应商统计，不从字符上限推导。

## 7. 语音模型与安装

先按[模型包说明](SPEECH_MODEL_PACKAGES_ZH.md)准备四个固定包。Qwen3-TTS 配方需要 Base 权重、codec 和默认 voicepack，不能只导入单个 GGUF。权重总大小不是运行内存估算。

| 编号 | 操作 | 预期 |
|---|---|---|
| M01 | 分别下载四个包，检查配方、revision，以及自动/官网/镜像线路 | 只有全部依赖、大小及 SHA 通过后可选用；语音模型页显示安装状态，继续/重试读取当前 HF 线路；固定元数据和非 HF 来源不被改写 |
| M02 | 大包下载中暂停、断网、重启、继续/重试 | 已有进度按传输能力恢复；缺文件包不可运行；失败信息可见 |
| M03 | 用离线打包工具生成 ZIP，选择导入；导入中取消 | 完整包可用；取消不会产生“可用但不完整”的资产 |
| M04 | 测试缺依赖、同大小错误哈希、越界/链接/ZIP64/重复路径、存储不足 | 合法 ZIP64 可导入；非法/不完整包拒绝，文件输出受限 |
| M05 | 在排队/运行/原生取消中尝试删除模型，再在完成后删除 | 被引用时阻止；停止且清理确认后可删；进程中断后的删除可恢复 |
| M06 | 删除有参考音色的非活动模型，重新导入相同名字 | 新资产不自动认领旧音色；原参考可试听/导出，需明确新建绑定 |

## 8. ASR、TTS 与聊天语音

建议使用自己准备的短音频：中英文各 10–30 秒、带静音的 2 分钟样例、一段超过 25 秒的转录样例，以及 WAV/MP3/M4A 中至少两种格式。长音频另测；不要只测试第一个分块。

| 编号 | 操作 | 预期 |
|---|---|---|
| S01 | 语音页授权麦克风，录音、停止、试听、丢弃；拒绝麦克风权限 | 可恢复且不崩溃；未授权不能偷偷录音；最近未提交录音重启后可恢复 |
| S02 | 录音时退后台、来电/焦点丢失，测试 10 分钟上限 | 停止录音并保留可处理文件，不自动恢复麦克风采集 |
| S03 | sherpa Whisper / Crisp Whisper 分别转录短/长文件 | UI 可交互，分块进度与内容正确，无重复末帧/最后一块丢失 |
| S04 | 编辑结果并导出 TXT；Crisp 原生分段结果导出 SRT | 编辑保留；SRT 时间单调且内容对应；sherpa 块级近似时间不提供 SRT |
| S05 | 转录一部分后取消、杀进程再启动 | 已提交块保留；任务为取消/中断，不自动重跑；显式重试创建新任务 |
| S06 | VITS 合成中英文适配文本、多个有效 speaker ID、语速 | 合成、播放、暂停、播放倍速、WAV 导出可用；无效 speaker 不访问越界 |
| S07 | Qwen3-TTS 默认 voicepack 合成；4000 字符和输出大小边界 | 兼容配方可执行，分块拼接不丢字/破坏代理对；超限有错误，不标完整成功 |
| S08 | 参考音色导入/录制 3–30 秒、填写转录、确认使用权、保存/合成试听 | 引用独立副本；24 kHz 标准化；绑定 revision；Crisp 标记/C2PA 行为保留 |
| S09 | 修改/删除音色，原模型缺失，再检查已入队任务 | 队列快照不变；活动引用不可删；失效音色可以试听/导出原资料 |
| S10 | 聊天麦克风转录后追加/替换/取消，期间编辑原草稿、切换会话/助手或删除目标 | 不自动发送、不上传音频；按助手/会话明确目标；已变草稿不可被旧结果覆盖，失效目标需重新确认 |
| S11 | 聊天回答含推理/工具过程，选择朗读 | 只用最终回答；经过明确合成/播放；不朗读工具参数和隐藏推理 |
| S12 | 同时提交多个 ASR/TTS，观察任务列表并取消中间队列项 | FIFO、最多 8 个活动项；被取消的排队任务不启动原生模型 |
| S13 | 播放中插拔耳机、切蓝牙、来电、开启录音或切换播放目标 | 焦点/播放状态一致；失焦暂停，不出现两个播放器争用 |

录音/合成输出仍需在真实 Android 编解码器上核对。文件扩展名可选不保证所有设备支持该容器/编码；不支持时应显示错误并保留原输入。

## 9. LLM 与语音并行及资源生命周期

用小型 GGUF 和 MNN 模型逐一运行，LLM 后端分别覆盖 CPU 与支持设备上的 Hexagon；OpenCL 仍只随包编译，不在用户后端列表开放。

| 编号 | 操作 | 预期 |
|---|---|---|
| R01 | 直接用本地助手聊天，不启动对外服务 | 使用私有 loopback/凭据；普通客户端不能借用私有鉴权 |
| R02 | 发布 LLM 服务并保持外部生成，同时提交转录/合成 | 语音直接使用自己的队列执行；LLM 模型与服务继续运行，不出现停止 LLM 的资源弹层 |
| R03 | 私用本地聊天正在生成或等待工具批准时录音转录、合成回答 | LLM 与语音可同时驻留；不取消当前 Run、不卸载 LLM；转录结果仍须明确追加/替换草稿 |
| R04 | 云端聊天同时进行本地语音 | 两者均可进行；语音不会停止无关远端 Run |
| R05 | 使用应用 Dio 分别在 MNN 首 token 前、普通解码、工具输出缓冲时停止，再立即发新请求/启动语音 | 只取消 HTTP；服务检测终止后取消本请求。原生未返回时新的 LLM 请求可为 429；语音独立开始，不以聊天结束或停服作为前提 |
| R06 | 注入语音 worker 退出且未确认 cleanup；另行验证停止后立即重启 | 未确认清理只隔离语音侧，需进程重启；dev.36 已移除 thermal/trim 启动拦截，正常释放后可立即启动下一模型 |
| R07 | 发布服务后退后台、锁屏、Activity 重建、反复开应用 | 同一业务 engine/队列，通知所有者不冲突；服务、日志和页面可恢复 |
| R08 | 停服、释放资源、切换 GGUF/MNN，多次循环 | 端口回收，无残留进程或持续增长的内存占用 |
| R09 | 延迟 MNN 原生退出超过停服等待窗口，或模拟卸载失败；之后再点击“停止” | 错误期间 LLM 资源仍占用，不能启新 LLM；语音仍可运行；恢复后可重试停止，不能假报启动成功 |
| R10 | 外部客户端占用 MNN 时让应用请求收到 429 并取消，再交错下一次请求 | 取消未接纳的请求不影响外部生成；旧请求的迟到回调不取消下一请求；无需私有请求头 |
| R11 | 流式/非流式分别测试 TCP reset、半关闭和网络静默中断 | 可观察的断开触发取消；合法半关闭仍能取得响应。记录平台检测时延，不以 FIN 或无响应推断原生释放 |
| R12 | 在通知权限等待、模型准备/加载、私用模型切换期间取消，立即重启或提交语音 | LLM 保持 stopping 和自身资源占用，新的 LLM 启动须等待；语音可独立开始；被取消流程不能迟到启动模型，失败可重试停止 |
| R13 | 转录/合成进行中启动、停止 LLM 服务，分别取消聊天和语音 | 各自启动与取消只影响本侧，语音任务、LLM 模型及前台通知所有者不会被另一侧误释放 |
| R14 | 语音清理失败后继续本地聊天、启动 LLM，再尝试下一语音任务和删除原语音模型/任务 | LLM 不受语音隔离影响；后续语音等待进程重启，原占用任务/模型不可删除 |

这些用例依据[HTTP 取消与资源释放设计](CANCELLATION_DESIGN_ZH.md)。JVM 使用真实 TCP 与阻塞 JNI 替身验证取消归属及等待顺序；还需真机验证 Dio 断开、MNN 批次和首次 GPU 调优。后者可能超过停服等待窗口，应保留资源并允许稍后重试。

对外 LLM 回归：分别测试 GET /v1/models、POST /v1/chat/completions 的流式/非流式、无 key/错误 key/正确 key、loopback/LAN、端口占用、客户端断开。使用当前 /v1/models 返回的模型 ID。不要把私用服务的临时端口当作发布端口。

示例（按测试服务配置替换）：

~~~bash
curl http://<device-ip>:8080/v1/models -H 'Authorization: Bearer <test-key>'
curl -N http://<device-ip>:8080/v1/chat/completions \
  -H 'Authorization: Bearer <test-key>' -H 'Content-Type: application/json' \
  -d '{"model":"<id-from-models>","messages":[{"role":"user","content":"你好"}],"stream":true}'
~~~

语音与 Agent 不新增对外服务；无需验收 /v1/audio 或 Agent 网关。原生发布服务不会因 thermal/trim 自动拒绝每个外部请求，此行为需纳入设备负载测试。

### 9.1 应用日志

从设置 → 应用日志进入；服务中心的日志菜单也应进入同一页面。dev.5 冒烟已检查入口一致、三类新增事件、组合查询、复制/导出、无结果禁用及正文标记抽查，范围见真机冒烟报告；dev.6 补测 agent.search 查询与搜索正文隔离，dev.7 检查头像与显示身份未进入日志。dev.9 检查 client.assistant.deleted 记录助手 ID 和会话数量，不含测试名称或草稿正文。下表的其余故障、长时负载及真实服务变体仍需验收；对应自动化已纳入当前 655 项全量回归。

| 编号 | 操作 | 期望 |
|---|---|---|
| L01 | 不启动 LLM，测试云端连接并聊天；再启动本地服务聊天 | client 分类能查到连接测试、模型发现、Run 与请求记录；服务日志仍可查看；日志页无需服务运行 |
| L02 | 分别触发正常回复、401/429、断流、首响应前取消与流式中取消 | request 记录结果、可取得的 HTTP 状态及耗时；同一 run 能关联多轮请求；不把 HTTP 断开当作原生释放/停止计费证明 |
| L03 | 工具批准、拒绝、重复批准；执行 Skill/MCP/网络搜索；断线中断远端副作用 | agent 可查授权和持久状态，重复批准不出现第二次执行；搜索可查供应商/结果数/耗时和失败原因，不含查询及结果正文；未知副作用保持 unknownOutcome |
| L04 | 语音模型下载/暂停/续传、合法/损坏包导入、取消导入、删除 | speech 可查资产 ID、阶段、结束/失败；无每个下载进度的重复刷屏 |
| L05 | ASR/TTS 正常执行、排队取消、执行中取消；LLM 同时运行 | 有入队、等待/运行、worker 加载/释放记录；取消后先等待清理，确认释放才记 resources_released=true；不影响 LLM |
| L06 | 使用测试手段模拟清理无法确认、同侧资源占用和重启 | 记录语音隔离或等待原因；不会把 cancelled 误报为资源释放；重启恢复不自动执行旧任务 |
| L07 | 录音权限拒绝、录音退后台/来电/耳机切换、播放完成、解码或导出失败、音色创建/编辑/删除 | 可查对应音频生命周期、错误类型/平台码；真实音频焦点与原生事件到达需设备确认 |
| L08 | 分类 + 最低级别 + 任务 ID 组合查询，复制并导出 | 三者相同；无匹配时禁用复制/导出；清空明确作用于全部分类，重开/重启后旧记录不再出现 |

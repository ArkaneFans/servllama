# 网络搜索工具

适用版本：ServLlama 2.0.0-dev.6+20。新增一个内置 Agent 工具 `web_search`，支持 Bing 和 DuckDuckGo，默认供应商为 Bing，两者均无需 API 密钥。参考 Kelivo 的公开搜索页面方案，复用现有助手授权、ChatRunner、工具回执与应用日志。

## 1. 如何使用

1. 打开「助手管理」，点击目标助手，进入「本地工具」标签。
2. 勾选「网络搜索」，选择供应商和结果数量，然后保存。每个助手独立设置；已有助手不会自动获得搜索权限。
3. 在聊天中选用这个助手，要求搜索一个问题并提供来源。AI 连接必须开启「支持工具调用」，所用模型也必须实际支持工具调用；本地与云端模型使用相同的工具流程。
4. 在消息内查看搜索状态、来源标题、链接和摘要，也可从聊天顶部「工具调用记录」集中查看保留的回执。点击来源会调用外部浏览器；原始参数与回执仍可展开查看。
5. 在「设置 → 应用日志」搜索 `agent.search`，查看供应商、状态、结果数及耗时。失败原因同时显示在工具卡片中。

授权意味着允许助手向所选供应商发送搜索词，无需逐次审批。搜索请求不携带 AI 连接密钥或自动附带完整聊天上下文；搜索词本身由模型根据对话生成，也会出现在当前会话的工具回执中。

## 2. 支持范围

| 项目 | 行为 |
|---|---|
| Bing | 读取 `https://www.bing.com/search` 的自然搜索结果，解析标题、来源和摘要 |
| DuckDuckGo | 读取 `https://html.duckduckgo.com/html/` 的 HTML 结果，排除广告并还原跳转链接 |
| 工具输入 | `query` 必填，去除首尾空白后 1–512 个 UTF-16 单元；`limit` 可选，1–10 |
| 结果数量 | 每个助手默认最多 5 条，可设置 1–10；工具请求不能突破助手上限 |
| 工具输出 | `provider`、`query`、UTC `retrievedAt` 和 `items`；每项含 `title`、`url`、`snippet` |
| 来源使用 | 工具说明要求将结果作为不可信网页数据，并引用返回的 URL；摘要不等于网页全文 |
| 失败 | 区分超时、限流、验证页面、未知页面结构、过大响应和连接失败；没有结果与请求失败分开表示 |

本次只提供这两家公开网页供应商。未加入付费搜索 API、独立代理配置、网页全文抓取、分页、图片搜索、搜索缓存或自动换供应商，也没有增加对外 HTTP 接口。公开搜索页面可能因网络、地区、验证或结构变化暂时不可用；用户可明确切换供应商。

## 3. 代码结构与执行闭环

| 位置 | 职责 |
|---|---|
| [web_search.dart](../../lib/features/agent/models/web_search.dart) | 供应商、助手搜索设置、结果和有限错误类型 |
| [web_search_service.dart](../../lib/features/agent/services/web_search_service.dart) | 独立 Dio 请求、取消、时限、响应上限、HTML 解析与搜索事件 |
| [agent_tool_service.dart](../../lib/features/agent/services/agent_tool_service.dart) | 按现有授权暴露工具，执行搜索，保存结果或失败回执并交还 ChatRunner |
| [assistant.dart](../../lib/features/assistants/models/assistant.dart) | 在现有助手 JSON 内持久化 `webSearch`，旧配置使用默认值 |
| [chat_run_config.dart](../../lib/features/chat/models/chat_run_config.dart) | 冻结当次供应商与结果上限；撤销搜索授权或更换供应商时停止受影响的旧 Run |
| [agent_permissions_page.dart](../../lib/features/agent/pages/agent_permissions_page.dart) | 在现有授权页编辑供应商与结果上限，文案正常本地化 |
| [web_search_receipt.dart](../../lib/features/agent/widgets/web_search_receipt.dart) | 在工具过程页显示来源、摘要和失败提示，按用户点击打开来源 |

执行路径为：助手授权 → 当次 Run 快照 → 模型返回 `web_search` 调用 → 校验参数和当前授权 → 写入执行状态 → 搜索 → 保存回执 → 交给模型续答。搜索失败也形成回执，模型可以解释失败；不会以空结果掩盖异常。

搜索设置随助手现有 JSON 保存，没有新表、数据库迁移、全局搜索注册表或第二套 Agent 调度器。搜索供应商与 AI 连接供应商相互独立。结果上限调整在下次 Run 生效；供应商变更会撤销旧 Run 的外发授权。关闭页面不会中断后台执行，停止聊天通过原有 CancelToken 取消该次搜索。

已有 Run/call 的成功回执直接复用，不重复发送搜索；失败或中断的同一调用不会自动重放。历史回答的「重新表述」仍只使用已有内容；明确重新执行任务才建立新的 Run。后续模型工具调用继续受原有轮次、工具次数、上下文和总时限预算约束。

## 4. 上限、日志与失败处理

- 每次搜索总时限 20 秒。搜索使用独立请求 token；搜索自身超时不会取消整个聊天，聊天主动取消会传递到搜索请求。
- HTML 实际读取量最多 2 MiB，解析在后台 isolate 执行。最多跟随 3 次跳转，只接受所选供应商域内的 HTTPS 跳转。
- 标题最多 240 个 Unicode 字符，摘要最多 800 个，来源 URL 最多 2048 个单元。结果去重，只接受不含用户凭据的 HTTP/HTTPS 来源链接；不会自动请求这些来源。
- 所有结果项的 JSON 合计最多 12 KiB，为查询和元数据保留空间，完整回执不触发既有 16 KiB 工具结果截断。来源列表始终来自保存的结构化结果。
- `agent.search.started` / `agent.search.finished` 写入现有 `AppLogger` 的 `agent` 分类，记录 Run/call、供应商、查询长度、上限、结果数、耗时、状态与有限失败原因/HTTP 状态码。
- 搜索日志不记录查询正文、摘要、来源 URL、HTTP 头或 AI 密钥。业务回执与诊断日志的内容边界不同；删除会话沿用现有回执清理流程。
- 不绕过验证页面，不自动重试或换供应商。遇到公开页面结构变化时报告解析失败，避免错误宣称「没有搜索结果」。

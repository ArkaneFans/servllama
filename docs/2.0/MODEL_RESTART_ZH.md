# 模型停止与重新启动：移除压力准入拦截

2026-10-06，`2.0.0-dev.36+50`。

## 原因与决策

2.0 曾新增 Android 内存/温控监听：收到内存回收信号后设置压力标记，30 秒后才复查。停止并释放旧模型并不立即清除该标记，所以同引擎换模型、跨引擎启动都可能被阻止，等待后才恢复。聊天弹窗的错误文字还混入“原生清理未确认”，但对应判断只检查设备压力。

按用户要求删除整套应用层压力检查，恢复 1.x 停止完成后即可再次启动的行为。不是将 2.0 所有运行时代码回退到 1.x；助手模型选择、私用/对外服务、两引擎互斥和语音独立驻留继续使用当前实现。

## 实现范围

- 删除 Android `ResourceMonitor` 及 AppHost 注册，包括内存回收回调、温控监听、30 秒复查和压力 MethodChannel。
- 删除 Flutter 端监听初始化、压力标记、压力更新方法，以及聊天启动前的压力拦截。
- `ResourceCoordinator` 只管理同侧驻留凭据和清理隔离；不再根据设备内存/温度拒绝加载。
- 语音队列移除压力等待原因及提示文案，保留 FIFO、同侧资源占用等待与原生清理失败后的隔离。
- 删除退役机制的专用测试，原来借压力阻塞构造的语音等待测试改用真实驻留占用。新增连续同引擎换模型和跨引擎立即重启回归，覆盖私用与对外服务。

停止仍等待 llama.cpp 进程退出，或 MNN 服务停止和模型卸载确认。清理失败时不会冒充已释放；并发点击、取消中尚未完成的原生操作仍受原有保护。无需更改 mnn_engine、模型文件、数据库或依赖。

## 验收

1. llama.cpp 模型 A 启动 → 停止完成 → 立即选择 B 并启动；MNN 同样验证。无需额外等待 30 秒。
2. llama.cpp 停止后立即启动 MNN，再反向验证；聊天模型弹窗、输入栏服务快捷入口和服务器页分别覆盖。
3. 运行中的引擎停止失败或仍处于停止过程中，不应启动第二套 LLM。该保护不属于已移除的设备压力机制。
4. LLM 与语音可以独立启动；语音任务仍按 FIFO 执行，取消后等待真正释放再处理下一条，清理无法确认仍提示重启。
5. 后台返回或系统压力通知不再产生应用层的压力等待提示；模型本身的加载、内存分配或系统进程终止错误仍由原有错误处理接管。

自动化使用受控引擎替身，不能替代真机模型启停。当前 ADB 无设备，以上真实模型操作留待真机验证。

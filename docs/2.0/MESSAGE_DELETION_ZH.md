# 消息版本删除与工作区移除

适用版本：ServLlama 2.0.0-dev.11+25，2026-09-27。此次修改仅在应用侧完成，不修改 mnn_engine 或参考仓库。

## 功能与交互

消息拥有自己的版本；每个生成版本通过 `runId` 关联生成记录与工具回执。删除不再只隐藏文字，关联记录也从会话汇总中清理。

| 操作 | 结果 |
|---|---|
| 多版本消息 → 删除本版本 | 确认后删除当前选中版本；优先显示前一保留版本，删除首版本则显示剩下的第一个版本 |
| 多版本消息 → 删除全部版本 | 确认后移除整条消息及其所有版本 |
| 单版本 / 旧无版本消息 → 删除 | 只显示一个删除入口，确认后移除整条消息 |
| 编辑用户消息 | 产生可切换的用户版本；用户和助手消息使用相同的版本切换、删除规则 |
| 取消确认 | 不改变消息、版本或工具记录 |
| 生成中 / 等待工具审批 | 禁用消息管理；执行器与持久层共同防止删除活动回复 |

确认框说明关联的工具调用和生成数据一并清理、操作无法撤销。删除保留后续消息；不会自动重跑后续回答。确认使用打开操作菜单时的消息快照，期间版本或消息改变则拒绝操作，避免删错版本。菜单可以滚动，兼容窄屏和大字体。

~~~text
助手头像  助手名称
  工具调用 · 1 次
  ✓ 当前时间    已完成
  回答正文
  时间 · 实际模型
  [上一版] 2/3 [下一版]   [更多]

  更多：复制 / 编辑 / 重新表述 / 重新执行任务（如可用）
        朗读（如可用）/ 删除本版本 / 删除全部版本

  删除本版本 → 确认 → 1/2；工具卡片同步切到保留版本
  删除全部版本 → 确认 → 消息和对应会话汇总记录消失
~~~

## 数据与实现边界

沿用 `ChatProvider → ChatRunner → ChatSessionRepository`，不新增删除管理器、回收站、后台清理队列或数据表。`ChatMessageRecord.withVersion` 统一恢复正文、思考、作者、时间、模型、附件和 Run，编辑与切换也复用此转换。

`commitMessageDeletion` 在一个 SQLite 事务中完成：

1. 复查消息快照、会话归属/索引和活动 Run。
2. 删除选中版本并保存保留版本的消息头，或删除整条消息及所有版本。
3. 收集删除范围内的 Run，仅当没有其他现存消息或版本引用时，删除 `tool_invocations` 与 `generation_runs`。同一个 Run 的共享引用不会误删。
4. 提交会话索引与附件删除标记。任一步数据库失败，消息、版本、回执、索引和标记一起回滚。

事务成功后才更新 Provider 可见消息和清理物理附件。只清理 `chat_attachments` 下没有现存消息/版本引用的应用自有文件；共享图片、外部原文件、语音任务及参考音色继续保留。文件清理失败保留原有持久删除标记，下次打开仓库重试。汇总页订阅聊天状态，重新查询已提交的记录。

`GenerationRunRepository.deleteUnreferenced` 是共用的 Run 清理入口。取消没有文字、思考或工具回执的空草稿后，同样清理失去引用的 Run；有工具的空正文回复仍作为可管理的版本保留。重启恢复不会从 checkpoint 重建已经不存在的消息的版本。

启动继续恢复有效的未完成 Run。dev.15 移除早期 2.0 的 `messageRunOwnershipV1` 一次性历史扫描；正常消息/版本删除仍在事务内删除失去引用的 Run 与回执，恢复也不得重建已删除消息。

删除针对本地消息与记录，不撤销此前已完成的远端 MCP 操作，也不删除用户已导出的副本。应用诊断日志仍遵循既有容量/轮转规则，只记录元数据，不保存工具正文。

## 移除会话工作区

| 移除 | 保留 |
|---|---|
| 会话文件页面、会话文本导入、文件预览/管理入口 | 聊天图片附件、语音输入/输出和模型管理 |
| 内置 `list_files`、`read_file`、`write_file` 及其授权 | `clock`、`ask_user`、`web_search`、按所选 Skill 开放的 `read_skill` |
| `ConversationWorkspace` 及文件写入审批、目标哈希复核 | 远程 MCP 工具授权、逐次审批和未知结果处理 |
| 将大工具结果写成会话文件、提示模型用 `read_file` 继续读 | 有界工具回执、参数/结果展示及用户手动导出回执文本 |

远端 MCP 的能力由用户配置的服务器提供，即使工具操作服务器上的文档，也不属于被删除的本地工作区。静态 Skill 的包内资源读取继续受其现有路径和权限边界约束。

汇总页更名为“工具调用记录”。导出只使用当前回执中已保存的结果，不再读取工作区文件或按旧 `write_file` 参数重建文件。

单次保存并返回给模型的工具结果上限为 **16 KiB UTF-8（包含截断提示）**。超过上限时在完整 Unicode 字符边界截断，保存 `resultTruncated=true`，卡片提示仅可查看或导出已保存的片段。成功和明确失败的 MCP 结果都遵循该规则；超长 JSON 可作为普通文本片段查看。不会再声明存在未保存的完整结果。搜索仍在其结果预算内保留可解析的来源结构。

## 旧数据处理

- `AgentRepository.retireWorkspace` 使用现有元数据标记幂等执行，剔除助手中三个旧文件工具权限并递增配置 revision。其他工具、Skill、MCP 绑定和历史 Run 配置快照保留。
- 历史文件工具回执保持只读，随所属版本删除；旧大结果回执去掉 `artifactPath` 和“完整结果已保存”的过期指引，标记为截断片段。
- 打开聊天仓库时，只将已登记的 `artifacts.owner_kind='conversation'` 置为待删除，复用已有清理流程。路径必须位于应用支持目录的 `workspaces/<ownerId>/`，且实际文件解析后仍在同一所有者目录内。
- 不递归扫描目录推测可删文件；未登记文件、外部原文件、越界路径和符号链接目标不删除。路径不合法或暂不可清理的登记项保留待处理状态，不扩大清理范围。空目录可以保留。
- Schema 仍为 4；没有新依赖、新执行器或新的文件兼容层。

待真机最小冒烟：

1. 在测试助手开启时间和提问工具，生成含工具回复，再重新执行一次得到两个版本。
2. 删除本版本，确认相邻版本及其卡片正确；汇总仅剩保留版本的回执。
3. 再生成一版，删除全部版本，确认消息与汇总对应记录消失；后续消息不受影响，冷启动后不复活。
4. 编辑用户消息，切换版本后删除其中一版；取消删除确认时数据不变。
5. 权限页无三个文件工具，汇总页无工作区/文本导入；如有受控 MCP 服务，再检查超长结果的截断提示与回执导出。

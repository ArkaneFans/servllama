# Hive → SQLite 存储迁移

> 最新进展（dev.15）：Drift 真机覆盖升级与 SQLite 写入冒烟通过，已清理四类早期 2.0 迁移。当前结果及兼容边界见 [真机验收与迁移清理](DRIFT_DEVICE_ACCEPTANCE_ZH.md)。

2026-09-30，ServLlama `2.0.0-dev.14+28`，SQLite schema 5。依赖使用 Drift 2.31.0、sqlite3_flutter_libs 0.5.39 和锁文件中的 sqlite3 2.9.4；保留 Hive 依赖及旧适配器用于升级读取。mnn_engine 及上游仓库未修改。

## 范围与存储归属

| 数据 | 迁移后的唯一业务来源 |
|---|---|
| 会话、消息、消息版本 | 原有 SQLite 表；已迁移的 2.0 数据不再导入旧聊天 |
| GGUF 模型详情 | `model_assets.manifest.gguf`；与资产 ID、名称、路径、能力标记同一行 |
| 语言模型下载任务，含 MNN 下载 | 新表 `download_tasks`；各文件进度等完整任务快照保存在 payload |
| 助手、供应商、Skill、MCP、Run、语音任务 | 沿用已有 SQLite 表 |
| 用户档案与简单偏好 | SharedPreferences |
| 凭据 | Secure Storage |
| 模型、投影文件、下载分片、音频与附件 | 原有文件位置；迁移只转换元数据 |
| MNN 插件持有的模型目录 | 插件继续管理，应用只维护共有资产索引 |

`LocalModelRepository` 保留文件管理职责，改由 `GgufModelStore` 读写现有资产表；不增加第二个 GGUF 注册表。迁移匹配旧 libraryId 或文件路径，保留现有 2.0 资产 ID、附加 manifest 字段，以及 GGUF 原始 ID、导入时间、来源、revision、视觉开关和所有投影文件映射。以后改名或切换投影时，详情与索引一起提交；统一资产查询不再从旧 GGUF 来源重复覆盖这些数据。

下载仓库写入前将可变任务转换成 JSON 快照，完整保存 requestedModelName、targetModelId、状态、网络暂停标记、校验值、已收字节数和文件完成标记；重新读取返回独立对象。文件传输与最终入库继续使用现有下载恢复逻辑，并不宣称数据库事务可以覆盖文件复制或移动。

## 启动流程和页面

复用 `BootstrapGate`，参考 Kelivo 的迁移阶段展示与失败重试交互；不复制其备份、修复、跳过和数据库安装框架。

1. 进入业务首页前检查数据库和迁移标记。新安装或已经迁移完成时只显示普通启动状态。
2. 有待迁移的旧数据时显示“正在升级应用数据”，依次显示读取聊天、模型、下载任务，保存记录和校验记录。
3. 已知工作量的步骤显示“当前步骤：已完成 / 总数”，不把它当成整体百分比；读取时显示不定进度。界面可以滚动，系统返回不绕过初始化。
4. 事务成功、凭据清理及原有启动恢复完成后自动进入首页，无额外确认。
5. 失败时停在当前步骤，显示错误及重试按钮，不创建业务 Provider，不提供跳过或清空数据按钮。排除问题后可在当前进程重试，也可重启应用。

迁移本身不加载模型、不联网、不下载、不移动模型和分片。成功进入应用后，语言模型下载仍遵循原规则：中断的活跃传输回到队列，受网络设置约束；手动暂停的任务保持暂停，完成记录由已有逻辑清理。LLM/Agent/语音中断任务仍按各自原有规则恢复状态，不自动重放推理。

## 一致性与失败恢复

- 旧聊天标记 `legacyImportComplete` 保持不变；新增 `legacyInventoryImportComplete`，兼容已有 2.0 开发版的聊天迁移状态。
- 一次启动中所有待导入记录和对应完成标记处于同一个 SQLite 事务。模型和下载完整 payload 回读校验通过后才提交；目标记录冲突会失败，不静默丢弃旧任务。
- 写入、校验或提交失败时回滚。崩溃后按标记重新执行；成功后不再读取相应旧文件，因此 SQLite 中后续删除的记录不会在重启时复活。
- 旧 `.hive` 文件读取到内存后交给 Hive 解码，禁止对原文件做恢复、截断、压缩或清理。若只有 `.hivec`，读取该已压缩文件；若两者都有，遵循 Hive 的普通文件优先规则，但不删除任何文件。
- Hive 2.2.3 在解码失败时可能同时抛出内部 completer 的异步错误；读取范围内将它和返回 Future 的错误收拢为一次可见失败。损坏数据不会自动跳过或部分导入。
- 完成后继续保留旧文件用于排查，不再作为业务数据源，也不代表支持降级后数据同步。旧适配器保持冻结；新增数据只写 SQLite。
- 日志使用现有 AppLogger，记录 `storage.migration.started/completed/failed`、条数、阶段和异常类型，不记录模型路径、聊天内容、下载 payload 或凭据。

| 场景 | 操作与预期 |
|---|---|
| 1.x 覆盖升级 | 保留应用数据安装 dev.14；首次启动展示实际迁移阶段，成功后原聊天、模型及下载任务可见 |

| 再次启动 | 不重复迁移，设置及新产生/修改的数据保留；在测试副本删除的模型/任务不复活 |
| 错误与重试 | 在隔离测试数据中模拟损坏或写入失败，不能进入半迁移首页；解决问题后重试成功 |

不要在用户唯一的真实数据上故意制造损坏、清空空间或强杀写入。长历史、系统中断与磁盘故障的设备验证可单独安排；正常覆盖升级无需手动选择迁移文件。
